# 发行文案（Release Notes）

每个正式版本一份，文件名与 tag 一致：`<tag>.md`（如 `v2.0.0.md`）。

## 与 CHANGELOG.md 的分工

| | CHANGELOG.md | docs/releases/<tag>.md |
|---|---|---|
| 定位 | 完整变更清单，供追溯与自查 | 面向用户的发行文案 |
| 读者 | 开发者、issue 排查者 | 下载页面的普通用户 |
| 长度 | 不限，逐项列清 | 尽量短，几段说清"这一版在做什么" |
| 是否进 Release 正文 | 否 | 是（首选来源） |

## CI 如何取文案

`.github/workflows/release.yml` 的 `Generate release notes` 步骤：

1. 若存在 `docs/releases/<tag>.md` → **直接用它的内容**作为正文；
2. 否则回退到 `CHANGELOG.md` 中 `## <tag>` 段落（适合小版本，无需单独写文案）；
3. 无论走哪条路径，末尾都会附上「安装与运行须知」这段通用内容。

## 写文案的建议

- 首屏一句话说清"这一版最大的变化"（如"换了一副骨架"）；
- 分段讲**用户能感知到的变化**，不列内部重构与文件名；
- 明确写出**升级注意事项**（是否需要重装、数据是否保留、有无新增运行时依赖）；
- 详细清单不复制进来，一句话链到 CHANGELOG 的对应段落即可。
